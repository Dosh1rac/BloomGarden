# Как запускать и где живут данные

## Почему база «слетела» после передеплоя

Приложение хранит всё в SQLite-файле `garden.db`. На Railway контейнер
пересоздаётся при каждом деплое, а вместе с ним стирается и файловая система.
Поэтому база каждый раз возвращалась к версии, лежавшей в репозитории.

Теперь базу нужно хранить на **постоянном томе (volume)**.

## Включить постоянное хранение (Railway)

1. Открой сервис в Railway → вкладка **Variables / Settings** → раздел **Volumes**.
2. **Add Volume**, имя, например, `garden-data`.
3. Mount path: `/data`.
4. Передеплой сервис.

Код сам подхватывает `RAILWAY_VOLUME_MOUNT_PATH` и положит базу в
`/data/garden.db`. Если нужно другое место — задай переменную `DB_PATH`.

Проверить, что всё включилось: открой `/api/db-info`. Должно быть:

```json
{"path": "/data/garden.db", "persistent": true, "exists": true, "size": 20480}
```

Если `persistent` равно `false` — том не подключён, и данные снова пропадут
при следующем деплое.

## Бэкапы

- Кнопка **«💾 Скачать бэкап»** в саду (левая панель) отдаёт полную копию базы.
- То же самое: `GET /api/backup`.
- Дополнительно при каждом старте приложения рядом с базой создаётся суточный
  снимок `garden-ГГГГММДД.db` (хранятся последние 7).

Скачивай бэкап перед крупными изменениями — файл можно просто положить обратно
в том под именем `garden.db`.

## Локальный запуск

Без переменных окружения база создаётся рядом с кодом:

```bash
uvicorn backend.main:app --reload --port 8000
```

`backend/garden.db` в git больше не хранится: иначе деплой затирал бы живые
данные старой копией.
